## 收尾分析（shrinkage + gating + 物理上限）

原始 DP 路径净伤 RMSE（gamma 越硬越接近 CF），但 drift 方向信号真实存在。按"弱信号正确用法"= 收缩 + 门控：

### 收缩（把 DP drift 当观测，朝 0=CF 收缩）
| beta | level-only RMSE |
|---|---|
| 0.0 (=CF) | 13.095 |
| 0.2 | 12.669 |
| **0.22 (最优)** | **12.665** |
| 0.5 | 13.362 |
| 1.0 (原始路径) | 17.338 |

→ 最优收缩后总 RMSE ≈ `sqrt(12.67² + 9.035²)` = **15.56**（CF 15.91）。**净增益仅 ~0.35**。

### 门控（高置信子集 drift_corr，加权）
| 子集 | drift_corr | 井数 |
|---|---|---|
| ALL | 0.24 | 773 |
| GR miss<0.2 | 0.20 | 275 |
| prefix_corr>0.85 | 0.31 | 244 |
| typewell rank≤3 | 0.09 | 100 |
| GRmiss<0.2 & pcorr>0.85 & rank≤5 | 0.20 | 32 |

→ **没有任何干净子集把信号抬到可用水平（需 0.6+）**。门控救不回来。

### 物理上限（为什么必然弱，且 NCC 也救不了）
近水平 lateral 段 `post_md_per_tvt ≈ 200`（每 1 ft TVT 走 ~200 ft MD）。well 沿 MD 的 GR 变化主要由**横向相变（areal 异质）**驱动，而 typewell 只编码**纵向 TVT 结构**——两者解耦。故 even oracle-TVT 处 GR corr 仅 0.665、还原 drift corr 仅 0.24；窗口 NCC 模式匹配也无效（轴不同）。typewell 对齐信号被物理性封顶。

## 最终判定（路线已彻底约束）

**typewell 约束对齐 = 弱信号，物理封顶 ~0.35 RMSE，门控无法放大 → 不作为 gold trunk。**

至此**所有候选 drift 来源全部量化封顶**：
- surface / Z / spatial 邻井：oracle 证伪（死）。
- typewell DTW：真但弱（~0.35），物理封顶，门控无效。
- 公开前沿 ≈ const oracle 9.04 → 全场基本无人吃到 drift，与上述一致。

**基础路线（建模起点，已约束死）：**
1. **地板 = carry-forward**（15.91）。这是绝对安全底座。
2. **shape 几乎免费**：对任何预测做 ~201 ft 平滑（smooth oracle 0.39）；但注意 CF 是常数、平滑无效，shape 只有在有真实路径时才拿得到——而我们没有可靠路径，故 swing 9.035 floor 暂不可触。
3. **唯一可加的真信号 = typewell DP drift 收缩 β≈0.2**，仅值 ~0.35，且要带 hidden-safe 兜底；可选、低优先。
4. 放弃 surface/spatial/Z/PF/大 stack。
5. 真正建模时，增益只能来自**比上述更强的、尚未被本轮触及的信号**（若存在）；否则这是一道"地板 + 微弱 drift"的鲁棒性竞赛，金牌取决于**长尾井不翻车 + 工程稳定**，而非模型复杂度。
