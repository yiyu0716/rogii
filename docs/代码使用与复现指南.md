# ROGII 核心代码使用与复现指南

## 1. 目的与边界

这个包保存的是项目最终值得保留的五个模型族与第一名 Ruby 复现源码，不保存历史试验缓存。这样做的原因是：同一个模型在项目中曾被复制到大量 Kaggle Kernel、候选池和旧 OOF 目录；这些副本既容易混淆验证口径，也无法作为干净的复现起点。

本包的统一约定如下。

1. 验证文件固定为 `metadata/geo_kmeans_5fold.csv`，一个 held fold 中的整口井不参与该 fold 的训练、imputer、selector、后处理参数或特征先验拟合。
2. 训练标签为完整训练井的 `TVT` 或相对最后可见 `TVT_input` 的 drift。验证/测试未知段的真实 TVT 不能作为输入。
3. 测试阶段只能使用全段水平井 `MD/X/Y/Z/GR`、可见 heel TVT 前缀、对应 typewell 和从训练数据得到的模型资产。
4. 所有模型输出按 `TVT_hat = last_visible_tvt + drift_hat` 回到提交坐标。不要把不同 drift 参考点的预测直接融合。

原项目默认目录为 `/root/rogii`。若在其他位置使用，请先调整每个脚本顶部的 `ROOT`、`DATA_ROOT` 和资产路径；这些绝对路径没有被隐藏，以便审计数据来源。

## 2. 环境与数据

建议 Python 3.11/3.12、Linux、CUDA PyTorch 环境。核心依赖为 `numpy`、`pandas`、`scipy`、`scikit-learn`、`lightgbm`、`joblib`、`torch`、`timm`、`numba`、`pyarrow` 与 `safetensors`。不同模型臂不需要同时安装所有依赖：full249/SG-path 主要使用 LightGBM，WARP/GSN/Ruby 使用 PyTorch，HMM 可使用 PyTorch 或 Numba CUDA。

比赛数据路径应包含：

```text
datasets/rogii-wellbore-geology-prediction/
  train/{well_id}__horizontal_well.csv
  train/{well_id}__typewell.csv
  test/{well_id}__horizontal_well.csv
  test/{well_id}__typewell.csv
```

训练数据的完整 `TVT` 仅供训练和 OOF 评估；测试井未知段没有该列。typewell 的 TVT/GR/geology 是题目提供的参考剖面，属于合法推理输入。

## 3. full249：表格安全锚

入口：

```text
models/full249/rebuild_full249_geo_kmeans_fold_oof.py
models/full249/full249_reference_bundle.py
models/full249/public_xgb_train19_source.py
```

`public_xgb_train19_source.py` 是 249 维特征构造的基础实现。特征包括井眼几何、heel 延续、typewell-GR 对齐、PF/likelihood、beam/path、ANCC/NCC、空间/地层先验及多个候选的分歧。`rebuild_full249_geo_kmeans_fold_oof.py` 以 Geo5 held fold 重建各 fold 的训练派生状态、生成 validation feature，再训练对应 LightGBM；它故意不接受旧 OOF 缓存作为 held-fold 标签特征。

典型流程：

```text
训练四折 -> 构造该 fold 的训练派生先验/feature frame
       -> 训练 LightGBM drift 模型
held fold -> 用相同的 fold 状态构造 feature frame
          -> 预测 drift -> 写入 OOF
五个 held-fold OOF -> 统一 RMSE
```

`train_full249_upf_honest_oof.py` 与 `train_full249_fg2_nestedupf_a2_onefold.py` 是后续 full249 扩展的训练示例，保留它们是为了说明 nested 训练资产的边界，而不是建议将它们与基础 249 维结果混用。

## 4. WARP：序列形状专家

入口：

```text
models/warp/build_gr_features.py
models/warp/warp_model.py
models/warp/train_warp.py
models/warp/train_ema.py
models/warp/deploy_warp.py
models/warp/train_warp_raw_strict_geo5_20260729.py
```

WARP 将水平井的 GR、导数、平滑/包络、局部方差和轨迹量做成 15 通道序列；typewell 的 GR 与相对 TVT 做成 token。模型经 typewell cross-attention 和一维 SCA-U2Net 预测逐步 drift increment，再通过累积和恢复连续路径。`deploy_warp.py` 保持训练/推理的特征语义一致，`generate_exp207_honest_warp_oof_20260718.py` 展示了按 held fold checkpoint 生成 standalone OOF 的做法。

关键限制：每个 fold 的归一化统计量和 checkpoint 只能作用于其 held fold；测试时才允许五个全训练 fold 模型平均。WARP 用未知段 GR 是合法的，因为它是比赛测试输入；不能用未知段 TVT 对齐 typewell。

## 5. HMM：显式连续路径解码

入口：

```text
models/hmm/exact_hmm_posterior_source.py
models/hmm/exact_hmm_smoother_geo5_20260726.py
models/hmm/hmm_grid_smoother.py
models/hmm/hmm_h_emission.py
models/hmm/run_hmm_h_oof_geo_kmeans.py
```

HMM 在 `U = TVT + Z` 空间建立 typewell level 的离散状态格点。emission 来自水平井 GR 与在候选 TVT 处插值的 typewell GR 的差异；transition 限制相邻 MD 位置的 level/rate 改变。forward-backward 或 Viterbi 因此能在多个单点 GR 匹配中选择一条连续路径。

`exact_hmm_posterior_source.py` 是发射概率、状态和 GPU decode 的基准来源；`hmm_h_emission.py` 是仅利用可见 heel 做 GR 噪声/幅值适配的发射版本；`run_hmm_h_oof_geo_kmeans.py` 负责按 Geo5 输出 HMM OOF。不能用 held fold 的真实 TVT 标定 emission、选状态或调 transition。

## 6. GSN：二维 SDF/segmentation 路径模型

入口：

```text
models/gsn/src/dataset.py
models/gsn/src/model.py
models/gsn/src/train.py
models/gsn/src/infer.py
models/gsn/gsn_v351_honest_oof_geo5_20260728.py
models/gsn/train_gsn_v351_strict_geo5_20260729.py
```

GSN 将候选 TVT level 与水平井 MD 组成二维图。网络有两类头：SDF head 预测每个格点到真实路径的有符号距离，segmentation head 预测路径附近概率。解码时可按每列最小绝对 SDF、Viterbi 路径或两者组合取出连续 TVT 路径。`gsn_v351_honest_oof_geo5_20260728.py` 使用 canonical Geo5 与 held fold checkpoint 做推理，并一次输出多种 decode profile，避免把模型收益和后处理收益混在一起。

源码来自队友 v3.51 实现，`src/model.py`、`src/dataset.py` 与 `src/train.py` 是训练主链。权重不在包中，必须以训练日志、fold map 和 checkpoint 校验和共同记录其来源。

## 7. SG-path：候选路径与选择证据

入口：

```text
models/sg_path/live_v2_candidate_generator.py
models/sg_path/sg_path_online_lib.py
models/sg_path/member_path_online_lib.py
models/sg_path/candidate_cluster_tabular_v1.py
models/sg_path/build_strict_oof_sg_paths_geo5.py
```

SG-path 不是一个额外的 TVT 标签来源。它以 anchor/WARP/HMM/GSN 的可见推理路径为起点，在 U-space 生成多个连续候选，然后以候选特异性证据评分。cluster selector 学习“哪一簇候选在类似训练井上更可靠”，member selector 在 cluster 内排序具体 path；二者训练时只可使用其他四折生成的候选标签，held fold 仅做推理。

`build_strict_oof_sg_paths_geo5.py` 展示完整的 fold-pure 版本：每一 held fold 独立拟合 formation prior、生成候选、训练 ExtraTrees/LightGBM selector，并对该 held fold 预测。候选数、diversity、KEEP 等超参数改变的是候选覆盖与后验收缩，不能把 oracle best candidate 当作线上特征。

## 8. 第一名 Ruby：0724v1 与 0803v2

目录：

```text
models/ruby_1st/source_0724v1/   公开原版
models/ruby_1st/source_0803v2/   公开原版
models/ruby_1st/work_0724v1/     Geo5、默认 no-XY 工作副本
models/ruby_1st/work_0803v2/     Geo5、默认 no-XY/no-target-PF 工作副本
```

公开代码构建固定 typewell level lattice，将水平井位置和 candidate TVT level 组成二维输入，学习每个位置的 conditional posterior。`run_geo5_repeat.py` 用本项目的固定 Geo5 划分替代原 split；三个 repeat 使用不同 seed，最终通过 `merge_geo5_repeats.py` 聚合 OOF。

严格工作副本的两个必要安全改动：

1. 默认删除全部 `geo_*` 邻井通道，并用零 placeholder 保留 Dataset API。因此不会读取邻井 TVT、做 XY 邻井搜索或聚类。
2. `0803v2` 禁用 PF cache 写入 suffix TVT，且 loader 遮蔽 target bins。公开实现曾可能通过 `common["tvt_target"]` 对齐 validation PF feature；该路径对严格 OOF 不可接受。

执行前需提供数据、GPU、ConvNeXt checkpoint 与每版本的 `cfg.pkl`。`models/ruby_1st/README.md` 给出准确命令。当前 strict 版本的数字不能与作者的含 XY/原协议 CV 直接比较。

## 9. 结果记录与提交

任何结果记录至少应包含：脚本 SHA256、Git commit、fold map SHA256、数据清单、训练/验证井数、输入 checkpoint SHA256、OOF 文件 SHA256、整体 RMSE 和按井 bucket 诊断。Kaggle 正式提交只能由在线 Kernel 生成 `/kaggle/working/submission.csv`；本地 OOF/CSV 只能用于诊断。

## 10. 源码包与运行资产的关系

本仓库的代码足以重新构造流程，但不等于立即可运行的“模型包”。重训/推理仍需要下列外部资产：竞赛数据、每 fold checkpoint、full249 fold-specific imputer/先验、WARP/GSN normalization、HMM grid 配置和 Ruby ConvNeXt checkpoint。它们必须在一次新实验中从对应训练 folds 重新产生或以可验证的 manifest 引用；不得从已删除的旧 cache 盲目恢复。
